# Стабильные SID исходников

Необязательный Babel-плагин `@virentia/core/compiler` назначает устойчивые относительно исходного кода SID импортированным вызовам `store`, `reactive`, `readonlyReactive` и `event`. SID сторов позволяют восстановить серверный [снимок scope](/ru/ui/ssr) на клиенте. SID событий обозначают объявления событий, но не добавляют состояние событий в снимок.

## Vite без JSX Virentia

Используйте отдельный адаптер, если приложение работает с Core и React, Vue или другим JSX runtime:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import virentiaCore from "@virentia/core/compiler/vite";

export default defineConfig({
  plugins: [virentiaCore({ namespace: "my-app" })],
});
```

Для сборки нужен Babel 7. Адаптер работает до обычных преобразований Vite, оставляет JSX и TypeScript для следующих этапов и обрабатывает обычные `.ts`/`.js`-модули состояния наряду с JSX-файлами. Он распознаёт именованные, переименованные и namespace-импорты из `@virentia/core` или `@virentia/ui`; одноимённые сторонние и затенённые функции не затрагиваются. `@virentia/ui/vite` уже включает Core-проход SID вместе с компиляцией нативного JSX Virentia.

Для других сборщиков доступен Babel 7 плагин `@virentia/core/compiler`: передайте имя файла и опции `{ root, namespace }`. Автоматический SID включает namespace, путь исходного файла относительно `root` и позицию вызова. Vite по умолчанию использует свой корень проекта. Для серверной и клиентской сборок сохраняйте одинаковые относительные пути и namespace; переопределяйте `root`, если корень Vite не совпадает с нужным корнем исходников. `sid: false` отключает автоматическую генерацию SID.

## Явные ID и снимки

Компилятор сохраняет явный SID в объекте метаданных. Без компиляции задайте его самостоятельно:

```ts
import { event, store } from "@virentia/core";

const user = store(null, undefined, { sid: "session/user" });
const changed = event({ sid: "session/changed" });
```

`serialize(scope)` включает материализованные записываемые сторы с SID. `scope({ snapshot })` лениво восстанавливает их значения до первого чтения или записи. Повтор SID в одном scope вызывает ошибку. Нативный UI Virentia добавляет к локальному SID путь экземпляра компонента; повторные вызовы одной фабрики вне такого владения требуют разных явных SID. Автоматические SID совпадают между сборками одного исходного кода, но не являются постоянными ключами схемы после редактирования файла. Для безопасной модификации вызова компилятору нужны явные аргументы и объект метаданных, записанный непосредственно в коде; spread аргументов или динамический объект метаданных дают диагностическую ошибку, если автоматические SID не отключены.
