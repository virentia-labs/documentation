# Владение моделями

Если родитель должен управлять ребёнком до появления DOM, создавайте ребёнка в его модели. Отображение получает уже готовый экземпляр.

В учебнике `BoardModel` владеет счётчиками через `children.many(CounterModel)`. Тот же граф можно создать заранее:

```tsx
const appScope = scope();
const board = scoped(appScope, () => BoardModel.create({
  id: "board",
  counters: [{ label: "Coffee", count: 2 }],
}));
render(() => <Board model={board} />, container, {
  scope: appScope,
});
```

`Board` и `BoardModel` здесь взяты из [примера учебника](./model-lists#complete-example); `scope`, `scoped` и `render` импортируются из UI. Родитель может добавлять счётчики ещё до рендера.

## Кто удаляет модель

`board.counters.remove(counter)` уничтожает дочернюю модель. `board.dispose()` уничтожает всю доску с детьми. Оба действия могут быть асинхронными; дождитесь их завершения, если важен teardown.

Само скрытие `<Counter model={counter} />` не удаляет переданную модель: ею продолжает владеть доска.

Без пропса `model` компонент создаёт экземпляр сам. Во вложенном компоненте он принадлежит модели родителя. Это подходит ребёнку, которым не нужно управлять заранее.

Один экземпляр имеет одно активное отображение. Чтобы одновременно показать два независимых счётчика, нужны два экземпляра.

Для автоматических экземпляров есть отдельная настройка [сохранения](../components).
