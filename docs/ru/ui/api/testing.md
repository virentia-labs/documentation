# Тестирование с Vitest

В тестах используются те же render и модели, что в приложении. Virentia не импортирует Vitest, не создаёт тестовый scope и не подменяет test. Scope и DOM-контейнер создаёт сам тест или ваша фикстура.

Для Vitest нужна DOM-среда, например happy-dom:

```ts
export default defineConfig({
  test: { environment: "happy-dom" },
});
```

defineConfig импортируется из vitest/config. В concurrent-тестах не храните общий scope или контейнер в переменной, которую перезаписывает beforeEach. Каждый тест создаёт свои значения; определение staticModel можно оставить на уровне модуля.

Достаточно обычного [API рендера](./rendering):

```ts
const appScope = scope();
const unmount = render(view, container, { scope: appScope });
await unmount();
```

Scope изолирует значения сторов и кеш нативных моделей. Отдельные корни изолируют DOM. Несколько корней могут намеренно использовать один scope; размонтирование одного не удаляет остальные. Готовая модель в model должна принадлежать scope рендера.

Для независимых scope не нужны глобальные сбросы. Освобождение ресурсов — отдельная задача: ждите unmount в finally или завершении своей фикстуры, когда нужно освободить DOM и lifecycle-ресурсы. Переданной моделью продолжает владеть её создатель; он вызывает dispose в конце её жизни. Автоматически созданная модель уничтожается при размонтировании, если keep не включён.

Bound-юниты экземпляра вызываются без окружающего scope. Для общих юнитов и создания модели используйте scoped(appScope, callback). Прямой await юнита Virentia сохраняет контекст; произвольный native promise — нет.

[Рецепт параллельности](../recipes/testing) проверяет одинаковые ID, bound-юниты и идентичность DOM через обычный test.concurrent.
