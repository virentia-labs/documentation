# Параллельность без глобальных очисток

Используйте обычный test.concurrent из Vitest. Scope и контейнер создаются внутри каждого теста. Обёртка или специальная настройка Virentia не нужны: scope принадлежит тесту, который его создал.

<UIWalkthrough kind="testing" />

Определение staticModel можно вынести на уровень модуля: общие юниты не означают общие значения. В разных scope разрешены одинаковые ID. Refs не перезаписывают другой document, а disposal одного экземпляра не отключает computed-подписки соседнего теста. Если сценарий зависит от фокуса или другого состояния document, создайте для него отдельный document.

В примере каждый тест сам создаёт scope, вызывает bound-действие и проверяет, что остались ровно те же button и текстовый узел. Finally ждёт локального завершения даже при упавшей проверке.

Для изоляции не нужны глобальные сбросы. Явно созданная модель остаётся собственностью создателя; keep сохраняет автоматически созданную модель, поэтому её надо уничтожить, когда тесту она больше не нужна. См. [правила Vitest и lifecycle](../api/testing).
