# Асинхронный поиск

Модель владеет query/results/pending/error и action ввода. Реакция action запускает поиск и использует свой AbortSignal, чтобы устаревший результат не заменил новый.

Поддерживаемый пример принимает search-функцию как зависимость фабрики модели. Обычный внешний Promise ожидается явно, после него записи выполняются внутри scoped(api.scope, ...). Это не притворяется автоматическим async-контекстом браузера.

```ts
const found = await search(text, signal);
if (signal.aborted) return;
scoped(api.scope, () => { self.results.value = [...found]; });
```

DOM подключает готовые юниты. Pending/error показываются named fragment-функциями с обычными if. Results здесь заменяются целиком: список полностью пересоздаётся и предупреждает в dev. Это сознательный выбор для нового набора результатов, не скрытое сопоставление ключей.

Для инкрементального получения отдельных результатов используйте mutableStore мутации либо нативный контейнер моделей. [Операции списков](../learn/model-lists).
